# i18n dizajn — bilingvalnost aplikacije (sr / en / de)

**Datum:** 2026-07-05
**Status:** na pregledu
**Grana:** `feat/i18n`

## Cilj

Cijela aplikacija (UI, email podsjetnici, izvozi dokumenata, AI asistent, URL putanje)
dostupna na tri jezika: srpski (`sr`), engleski (`en`), njemački (`de`). Jezik je
**fiksiran per-deployment** — bira ga isključivo developer kroz env varijablu.
Korisnici i administratori firme ne mogu mijenjati jezik. Nema baze podataka u
konfiguraciji jezika.

## Odluke (donesene tokom brainstorminga)

| Pitanje | Odluka |
|---|---|
| Izvor konfiguracije | Env varijabla, ne baza — jezik je build-time odluka developera |
| Biblioteka | next-intl, režim **bez i18n routinga** |
| Obim | Čitava app: UI, emailovi, izvozi (docx/pdf/xlsx), AI asistent |
| URL putanje | **Prevode se** (rewrite/redirect mapa per-deployment) |
| Sadržaj iz baze | **Ne prevodi se** — korisnički uneseni podaci ostaju kako su uneseni |
| Default jezik | `sr` — postojeći TEHPRO deployment radi bez ikakve promjene env-a |

## Arhitektura

### Konfiguracija jezika

- `NEXT_PUBLIC_APP_LOCALE` = `sr` \| `en` \| `de`; default `sr`.
- Novi `lib/locale.ts` po uzoru na `lib/brand.ts`: čita env, validira vrijednost,
  nepoznata vrijednost → fallback na `sr` uz upozorenje u build logu.
- `NEXT_PUBLIC_` prefiks: vrijednost se ugrađuje u build, dostupna i na serveru i u klijentu.

### next-intl bez routinga

- `i18n/request.ts`: `getRequestConfig` vraća locale iz env-a i učitava `messages/{locale}.json`.
- Server komponente: `getTranslations()`. Client komponente: `useTranslations()` preko
  `NextIntlClientProvider` u root layoutu.
- Nema middleware-a, nema cookie-ja, nema `[locale]` URL segmenta, nema locale negotiation.
- Provider prosljeđuje klijentu samo namespace-ove potrebne client komponentama
  (ne cijeli katalog) da ne naduva bundle.

### Katalozi prevoda

- `messages/sr.json`, `messages/en.json`, `messages/de.json` — jedan fajl po jeziku.
- Namespace-ovi po domenu: `common`, `shell`, `klijenti`, `termini`, `obilasci`, `plan`,
  `zapisnici`, `dokumenti`, `pregled`, `postavke`, `asistent`, `auth`, `email`, `izvoz`, `status`.
- Srpski katalog se puni postojećim tekstovima 1:1 (ijekavica ostaje kako jeste).
- Vitest test paritetnosti ključeva: sva tri kataloga moraju imati identičan skup
  ključeva — CI pada ako divergiraju.

### Prevodive URL putanje

- Fizička struktura foldera ostaje srpska (`app/(dashboard)/klijenti/...`).
- Centralna mapa `i18n/routes.ts`:

```ts
export const ROUTE_MAP = {
  klijenti: { en: "clients", de: "kunden" },
  termini:  { en: "appointments", de: "termine" },
  // ... svaki top-level segment i pod-segment koji se prevodi
}
```

- `next.config.ts` iz mape generiše:
  - **rewrites** — lokalizovana putanja servira fizičku srpsku rutu;
  - **redirects (308)** — srpska fizička putanja preusmjerava na lokalizovanu,
    da niko ne završi na `/klijenti` u engleskom deploymentu (i da stari
    bookmarci nastave raditi).
- Helper `href("/klijenti/123")` u `i18n/routes.ts` prevodi putanju za `<Link>`,
  `redirect()` i `router.push()`. Za `sr` je identitet. Dinamički segmenti (`[id]`)
  prolaze netaknuti. **Sve navigacije u kodu prelaze na ovaj helper.**

## Slojevi van UI-ja

- **Enum labeli** (statusi termina i sl. iz baze): mapiranje enum vrijednost →
  translation key (`status.zakazan` → „Zakazan" / "Scheduled" / „Geplant").
  Vrijednosti u bazi se ne diraju.
- **Datumi i brojevi:** next-intl `format.dateTime()` / `format.number()` sa
  locale-om deploymenta na mjestima prikaza korisniku; interna logika u
  `lib/date.ts` (računanja, poređenja) ostaje nepromijenjena.
- **Email podsjetnici** (`lib/email/templates.ts`): šabloni prelaze na ključeve iz
  `email` namespace-a, server-side `getTranslations({locale})`. Jezik emaila =
  jezik deploymenta.
- **Izvozi** (`lib/plan-izvoz/*`, `lib/zapisnik/*`, excel): hardkodovani naslovi,
  zaglavlja i labeli u generisanim fajlovima idu kroz `izvoz` namespace.
- **AI asistent** (`lib/claude/prompts.ts`): `SISTEM_PROMPT` dobija instrukciju
  „odgovaraj isključivo na jeziku X" izvedenu iz locale-a. Nazivi tool-ova ostaju,
  poruke asistenta prate jezik deploymenta.
- **Sadržaj iz baze** (vrste provjera, lokacije, bilješke...): ne prevodi se —
  firma na njemačkom deploymentu unosi svoje podatke na njemačkom.

## Redoslijed migracije

Grana `feat/i18n`; app ostaje funkcionalna nakon svakog koraka. Neizmigrirani
domeni ostaju hardkodovani (na srpskom) dok ne dođu na red — nema polu-prevedenog
stanja unutar jednog domena.

1. **Infrastruktura:** next-intl setup, `lib/locale.ts`, prazni katalozi sa
   `common` namespace-om, test paritetnosti ključeva.
2. **UI stringovi, domen po domen:** shell/navigacija → klijenti → termini →
   obilasci → plan/plan-aktivnosti → zapisnici → dokumenti → pregled/prikaz →
   postavke → asistent → auth stranice.
3. **Slojevi van UI-ja:** enum labeli, datumi/brojevi, email šabloni, izvozi,
   AI system prompt.
4. **URL prevodi:** route mapa, rewrites/redirects, prelazak navigacija na `href()`.

## Verifikacija

- Postojeći unit i e2e testovi rade pod default `sr` i **moraju prolaziti
  nepromijenjeni** — dokaz da srpski deployment nije regresirao.
- Test paritetnosti ključeva kataloga u vitest-u (dio `test:unit`).
- Sweep za zaostale stringove: grep za srpske dijakritike (`šđčćž`) u `app/`,
  `components/`, `lib/` na kraju svakog domena.
- Smoke provjera: `NEXT_PUBLIC_APP_LOCALE=en npm run build` (i `de`) + ručni
  pregled ključnih stranica.

## Rizici

| Rizik | Mitigacija |
|---|---|
| Propušteni stringovi (toast, Zod poruke, aria-labeli, `title` atributi) | Dijakritički grep + pregled po domenu |
| Kvalitet en/de prevoda | Prevode se tokom migracije; njemački katalog ide korisniku na provjeru prije produkcijskog de deploymenta |
| Slomljeni bookmarci nakon prevoda URL-ova | 308 redirecti sa srpskih putanja |
| Bundle naduvavanje kataloga | Klijentu se šalju samo potrebni namespace-ovi |
| Regresija srpskog deploymenta | Default `sr` + postojeći testovi bez izmjena assertion-a |
